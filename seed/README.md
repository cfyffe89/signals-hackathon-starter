# Hackathon tenant seed (organisers)

`scripts/seed_tenant.py` sets up a Signals tenant for the hackathon: team notebooks, one example experiment per use case, reagents and an inventory tree. **Dry run by default** (read-only). All content is synthetic demo data.

```bash
python scripts/seed_tenant.py                                   # dry run: what exists, what would be created, what's missing
python scripts/seed_tenant.py --apply                           # notebooks + experiments
python scripts/seed_tenant.py --apply --global                  # + materials + inventory (tenant-wide, can't be removed via API)
python scripts/seed_tenant.py --teams 6 --prefix HACK26 --event-date 2026-10-21
```
It uses `SIGNALS_BASE_URL` and `SIGNALS_API_KEY` from `.env`. Re-running is safe: it looks up every item by name (containers by barcode) and only creates what's missing. Each run writes `seed/output/seed_report_*.json`. After `--apply`, `seed/output/team_sheet_*.md` lists each team's notebook EID for the table sheets. `seed/output/` is gitignored.

## What gets created
| Part | Items | Use cases |
|---|---|---|
| notebooks | `HACK26 Reference Data`, `HACK26 Team 01..NN`, each with a `Team NN bench notes` experiment | all (teams write only in their own notebook) |
| experiments | Stability study request (3 formulation samples, study design) | stability study & test scheduling |
| | Step 1: Suzuki coupling; Step 1: amide coupling (reaction + stoichiometry + procedure) | next-step synthesis linker |
| | IC50 plate prep (dilution parameters + stock sample) | serial dilution calculator |
| | Analytical results (LCMS + NMR PDF reports) | instrument PDF parser |
| | Grignard addition (reaction, THF, timed procedure) | reaction hazard advisor, Smart SOP copilot |
| | Release testing request (3 tasks with Required By dates, one linked to the test experiment) + HPLC assay results | closing the loop, tasks to calendar |
| | Every experiment has Purpose / Conclusion text | report from a search |
| materials | 10 reagents with structure and CAS (the ones in the reactions) | shipment registration, containers |
| inventory | Site > Stability Lab > 3 chambers (25/60, 30/65, 40/75); Stockroom > Shelf A; one container per reagent, expiry dates from -10 to +700 days around the event | stability containers, expiry alerts |
| fixtures (not loaded) | `fixtures/incoming_shipment.csv`: 100 lines for the bulk-registration use case | register an incoming shipment |

Fixtures are generated by `scripts/make_seed_fixtures.py` (needs `pymupdf`) and committed.

## Tenant prerequisites (configure in the UI first)
The dry run lists anything missing under **Prerequisites missing**. The names are set in `seed_data.json` → `tenant`:
- Sample template `Sample` with `Description` and `Amount` fields. Task template `Test` with `Required By`, `Requestor Comment`, `Reference ID`.
- Materials library `Reagents (SNB)`. Its **mandatory** fields beyond name/structure/CAS need values in `material_field_defaults` or must be made optional.
- Location types `Site`, `Lab`, `Cabinet` (used for the stability chambers; a dedicated "Stability Chamber" type is better), `Stockroom`, `Shelf`. Container type `Bottle`.
- The API cannot create templates, inventory types or library fields. Those are Signals Configuration tasks.

## API behaviour this relies on (verified live, Sept 2026)
- A reaction **with a stoichiometry table**: upload a blank CDXML as a child → `POST /chemicaldrawings/{eid}/reaction/{reactants|products}` with `{"dataType":"smiles","data":…}` → `PATCH /stoichiometry/{eid}/{row_id}` with `{"values":{"eq":"1.2"}}` / `{"sm":"1.82 g","limit":{"value":true}}` → `POST /stoichiometry/{eid}/solvents`. Uploading an `.rxn` file gives a drawing with an **empty** stoichiometry table that can't be updated (403).
- Tasks: `POST /entities` type `task`, ancestors = the experiment, a task template, `fields` by id. `Experiment Link` is system-managed (400 "not editable"). Link to another entity with `Reference ID` = `{"values":[{"eid":"experiment:…"}]}`.
- Text elements: upload `text/html`. The filename becomes the element name, so leave off the extension.
- Uploads on a sleepy dev tenant can return 504 and still succeed. Check for the element before retrying.
- Materials: an asset's `name` is its material ID (e.g. `Reagents-005`). Find by chemical name with the tag `materials.<name field>` (`"in":"tags","as":"text"`).
- Inventory search (`source=IVT`) also returns the location/container **types**. Add `isTemplate = false`. Inventory write endpoints take the bare UUID, not `location:<uuid>:ivt`. Locations have no DELETE.
